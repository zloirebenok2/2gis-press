# 2пшы: сайт 2gis.press

Ежедневный выпуск о путешествиях, дорожных конфузах и юморе со всего мира. Сайт статический и собирается сам: по расписанию скрипт забирает свежие посты из открытых источников, раскладывает их по рубрикам, делает для каждой новости отдельную страницу и публикует сайт.

## Как это работает

```
sources.json            какие источники опрашивать (Telegram-каналы, RSS, Reddit)
content/editorial.json  ваши собственные публикации (можно ставить на будущие даты)
content/jokes.json      «Шутка дня» на главной, меняется сама каждый день
content/world.json      блок «Юмор со всего мира»
scripts/build.mjs       сборщик: собирает новости и генерирует сайт в public/
data/items.json         архив собранных новостей (обновляется ботом)
.github/workflows/daily.yml  расписание: 06:15, 12:15 и 18:15 по Москве
```

Каждый запуск:

1. Забирает посты из публичной веб-версии Telegram-каналов (`t.me/s/<канал>`), из RSS-лент и из Reddit.
2. Отбрасывает рекламу (стоп-слова `erid`, `#реклама` и другие из `sources.json`), слишком короткие посты, NSFW и закреплённые посты Reddit, дубли.
3. Определяет рубрику по ключевым словам, иностранные публикации идут в «Юмор мира».
4. Генерирует страницы:
   - `/` главная: выпуск дня, рубрики недели, шутка дня, юмор мира, билеты, архив;
   - `/n/<дата-заголовок-код>/` отдельная страница каждой новости с кнопками «Скопировать ссылку», Telegram, ВКонтакте, WhatsApp и системным меню «Поделиться» на телефоне; у страницы свои заголовок, описание и картинка для превью в мессенджерах;
   - `/day/ГГГГ-ММ-ДД/` выпуск за день, `/r/<рубрика>/` рубрика;
   - `/rss.xml`, `/sitemap.xml`, `/robots.txt`, `/404.html`, `CNAME`.
5. Сохраняет архив в `data/items.json` и публикует сайт. Новости старше 60 дней уходят из архива (`keepDays` в `sources.json`).

С новостями из чужих источников сайт показывает фрагмент (до 420 знаков), имя источника и кнопку «Открыть оригинал». Для Telegram-постов ниже подключается официальный виджет Telegram, который показывает пост целиком с картинками.

Яндекс Метрика (счётчик 113834141) и виджет билетов Travelpayouts стоят на каждой странице. Кнопки отправляют в Метрику цели: `share_copy`, `share_tg`, `share_vk`, `share_wa`, `share_native`, `source`, `world_tab`. Чтобы видеть их в отчётах, создайте в Метрике цели типа «JavaScript-событие» с этими идентификаторами.

## Запуск на GitHub Pages (бесплатно, без сервера)

1. Создайте репозиторий на GitHub и загрузите в него все файлы из этой папки (ветка `main`).
2. Settings, Pages, Build and deployment: Source = **GitHub Actions**.
3. Там же, Custom domain: `2gis.press`. У регистратора домена пропишите DNS:
   - четыре A-записи для `2gis.press`: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - CNAME для `www`: `<ваш-логин>.github.io`.
   После проверки включите **Enforce HTTPS**.
4. Actions, «Выпуск 2пшы», **Run workflow**. Дальше сайт обновляется сам три раза в день.

В логе каждого запуска видно, сколько постов дал каждый источник; если источник недоступен, он пропускается, а сайт всё равно публикуется.

## Запуск на своём сервере

Нужен Node.js 20 или новее. Пример для cron:

```
15 6,12,18 * * * cd /srv/2pshy && node scripts/build.mjs && rsync -a --delete public/ /var/www/2gis.press/
```

Веб-сервер отдаёт папку как статику; для красивых адресов `/n/.../` достаточно стандартного `index.html` в папке. Страница ошибки: `404.html`.

## Сайт одним файлом

`node scripts/single.mjs` после сборки кладёт в `public/2pshy.html` весь сайт одним файлом: стили, скрипты, шрифты и логотип встроены, а страницы новостей, выпусков и рубрик стали разделами файла с адресами `#n-<код>`, `#day-ГГГГ-ММ-ДД`, `#r-<рубрика>`. Расписание собирает его при каждом запуске, он доступен по адресу `2gis.press/2pshy.html`.

Файл можно выложить на любой хостинг как `index.html`, но он остаётся снимком на момент сборки: новые новости в нём появятся, только если пересобрать и перезалить файл. Превью ссылки в мессенджерах у такого файла общее для всех новостей, потому что часть адреса после `#` мессенджеры не читают. Для отдельных превью у каждой новости используйте многостраничную сборку из `public/`.

## Что менять руками

- **Источники:** `sources.json`. Добавить Telegram-канал: `{ "id": "...", "name": "...", "type": "telegram", "channel": "имя_канала", "home": "https://t.me/имя_канала", "lang": "ru", "fun": true, "weight": 2 }`. Подходит только публичный канал. RSS: `"type": "rss", "url": "..."`.
- **Свои публикации:** `content/editorial.json`. Пост с будущей датой появится на сайте в первую сборку после этого времени, так можно запланировать неделю вперёд. Пост с `"lead": true` станет главной историей своего дня.
- **Шутки дня и юмор мира:** `content/jokes.json`, `content/world.json`.
- **Оформление:** `src/site.css` (тема), `src/tokens.css` (цвета и шрифты), логотип в `static/assets/`.

Проверить локально: `node scripts/test.mjs` (разборщики на тестовых файлах), `node scripts/build.mjs` (сборка), затем открыть папку `public/` любым статическим сервером, например `npx serve public`.

## Ограничения

- Reddit иногда не пускает запросы с серверов GitHub. Тогда Reddit-источники пропускаются, остальные работают. На своём сервере это обычно не мешает.
- Посты публикуются автоматически без ручной проверки. Следите за списком источников и стоп-словами.
- Telegram-каналы, где посты только из картинок без текста, дают мало материала: такие посты пропускаются.
- GitHub отключает расписание, если в репозитории 60 дней не было коммитов. Бот коммитит архив после каждого сбора, поэтому расписание не засыпает.
